# js/nav.js

## Current state

How the navigation is built **today** — reference description, as opposed to the dated cycle entries below. Moved verbatim from `CLAUDE.md` on 2026-10-10 (phase 3 of the context-size split). ### Navigation: sidebar and icon navbar (2026-10-02, Navigation Cycle B2)

`js/nav.js` renders **one** `<aside class="pd-nav">` into `#nav-container` (direct children `.pd-nav-brand`, `.pd-nav-items`, `.pd-nav-actions`); CSS turns it into a fixed left sidebar at `min-width: 1024px` (open 240px, icon rail 68px via `html[data-sidebar="collapsed"]`, state in `localStorage['PDash_sidebarCollapsed']`) or a two-row icon-only navbar in normal flow below (56px + 52px + 3px magenta border = `--nav-top-h` 111px, breadcrumb hidden). The footer no longer exists anywhere (also removed from `login`/`activate`/`reset-password`). Rules to keep:
- **One DOM, unique IDs:** never render a second navigation; the 14 element IDs (`#nav-notif-btn`, `#nav-account-btn`, `#nav-profile-btn`, `#nav-settings-btn`, `#nav-send-notif-btn`, `#nav-change-pwd-btn`, `#nav-logout-btn`, `#nav-notif-badge`, …) are consumed by `notifications.js` and the wiring.
- **No jump on load:** `#nav-container` gets its size and navy background from CSS (fixed column / fixed-height bar), and `--sidebar-w` comes from the media query + the B1 head snippet's `data-sidebar`, never from JS.
- **Names:** menu entry = `<title>` = breadcrumb, from the `NAV_MAIN`/`NAV_GROUPS` model in `nav.js`: Pipeline, Portfolio, Planning, Master Data (the five `master-*.html` pages all use menu id `config`, title "Master Data" and breadcrumb Home > Master Data; their own name is their `<h1>` and the active sub-menu entry), Timesheets, User Admin, Team, Attribute Lists, DB Reset, Terms & Conditions (`js/lib/page-names.test.js` pins it). A new menu page must be added to the model and keep the three names equal. Page headings and exported file names are page content and keep their own wording.
- **Groups:** Admin (admin + sysadmin) and Sysadmin (sysadmin) are always-expanded sections ≥ 1024px; below, each is an icon button (`.pd-nav-group-toggle`) toggling a full-width white panel (10px side margins, one open at a time, Esc/outside tap closes — `navWireGroups`).
- **Menus:** the account menu and notification panel stay Bootstrap dropdowns; `navPopperConfig` (a `popperConfig` function evaluated on each open) places them: below the avatar/bell on small screens, right of the sidebar/rail otherwise (no flip). Unread bell = numeric badge + white background with red icon and border (`.pd-bell-btn.has-unread`).
- **Heights:** `.pb-board-root { height: calc(100vh - var(--nav-top-h) - var(--breadcrumb-h)) }` (`--nav-top-h` 0 on large screens, 111px below; `--breadcrumb-h` 32px measured, 0 below 1024px). If the navbar rows, breadcrumb padding or font change, re-measure (board bottom must equal `innerHeight`, no page scroll) and update the pins in `js/lib/nav-layout-guard.test.js`.
- **Stacking:** the sidebar/panels sit at `var(--z-fixed)` (300), below Bootstrap modals (1055); only while a menu or group panel is open (`#nav-container:has(.dropdown-menu.show, .pd-nav-group.open)` and the same on `.pd-nav`) the nav rises to 1050 so page-level fixed panels (e.g. `team.html`'s detail panel, z 1045) cannot clip the open menu.
- **Icons:** inline SVG (`navIcon(name, size)`, `currentColor`, `aria-hidden`), no emoji in navigation, dropdowns, modal titles or the notification banner; tokens `--icon-size-sm/md`.
- **Rail tooltips (2026-10-02, follow-up to B2):** in the collapsed sidebar (`navLayout() === 'rail'`, ≥ 1024px) the sidebar items (including the Admin/Sysadmin entries, which are permanent label-less rows there), the avatar (text = the user's email) and the bell ("Notifications") show a custom tooltip — one `#pd-tooltip` element in `<body>` (`position: fixed`, z-index 1051: above the raised nav, below modals), placed 10px right of the element and centred on it by `navWireTooltips`, because the scrolling `.pd-nav-items` would clip anything drawn inside it. Text comes from `data-tip`; every item also has an `aria-label` (the label span is hidden in the rail). The native `title` is removed in the rail and restored elsewhere by `navApplyTitles()` (called at init, on collapse/expand and on the 1024px query change): the open sidebar and screens < 1024px keep the native title and never show the custom tooltip. The tooltip hides on mouse out, focus out, click, Esc, dropdown open (`show.bs.dropdown`), items scroll, window resize, `navSetCollapsed` and when its anchor leaves the DOM (MutationObserver). Tests: `js/lib/nav-tooltip.test.js`, `#pd-tooltip` guards in `nav-layout-guard.test.js`.
Tests: `js/lib/nav-model.test.js`, `nav-behavior.test.js`, `nav-layout-guard.test.js`, `notifications-ui.test.js`, `page-names.test.js`, plus the updated `nav-shell*.test.js`/`foundations-guard.test.js`. Cache versions (after the rail-tooltip follow-up): `nav.js?v=17`, `style.css?v=21`, `notifications.js?v=3`, `tokens.css?v=9`, `core.js?v=13`. Detail: [this file](nav.md), spec `docs/superpowers/specs/2026-10-02-navigation-b2-sidebar-design.md`, plan `docs/superpowers/plans/2026-10-02-navigation-b2-sidebar.md`.

## Dropdown submenus (2026-09)

`adminHtml`/`sysAdminHtml` no longer render their pages as flat inline `<a class="nav-main-tab">` links — each is now a single Bootstrap dropdown (`<div class="dropdown">` wrapper, `<a class="nav-main-tab nav-role-menu-trigger dropdown-toggle" data-bs-toggle="dropdown">` trigger, `<ul class="dropdown-menu">` of `<li><a class="dropdown-item">` items), same pattern as the pre-existing `#nav-account-btn` dropdown further down in this file. Trigger labels: "⚙ Admin" (Config/Actuals Repository/User Admin/Team/Attribute Lists — the latter two added 2026-09 for the resource-allocation cycle's `team.html`/`attribute-lists.html`, `activeTab` ids `'team'`/`'attributelists'`) and "🔒 Sysadmin" (DB Reset/Terms & Conditions) — same role gating and hrefs as before, same preceding vertical divider.

The trigger (not the individual dropdown items) gets the `active` class whenever `activeTab` matches any page id inside its own submenu (`adminPageIds`/`sysAdminPageIds` arrays — keep these in sync with any future page added under a trigger); each `<li><a class="dropdown-item">` also keeps its own exact-match `active` class, independent of the trigger's.

Trigger styling (`.nav-role-menu-trigger` in `css/style.css`): white background + `var(--text-primary)` text, distinct from the plain-text main tabs — deliberately carries **no vertical margin** of its own; a code-review finding caught that a margin here does not collapse through the `<div class="dropdown">` wrapper (the actual flex child in the `align-items-stretch` tabs row), which silently grows that row's height beyond the other tabs' fixed 44px and eats into `pipeline.html`'s `calc(100vh - 206px)` navbar-height contract (see `docs/pages/pipeline.md`'s "Pipeline board layout (height math)" subsection) — the trigger relies solely on the already-shared `.nav-main-tab` `height: 44px` to stay the same size as its siblings. Any future style tweak to this trigger must not reintroduce margin/padding on the `<a>` or the `.dropdown` wrapper without re-verifying `pipeline.html`'s sticky column-totals footer stays fully visible for an admin/sysadmin user. The now-fully-dead `.nav-admin-tab` CSS rules (opacity dimming on the old flat links) were removed as part of this change.

## Navigation Cycle B2: sidebar, icon navbar, account and notifications (2026-10-02)

Spec `docs/superpowers/specs/2026-10-02-navigation-b2-sidebar-design.md`, plan `docs/superpowers/plans/2026-10-02-navigation-b2-sidebar.md`, merge `0cd5b23`. Frontend only.

**Structure.** `buildNavHtml(user, activeTab)` returns one `<aside class="pd-nav">` with three direct children: `.pd-nav-brand` (logo "PDash" / "P" in the rail, collapse button), `.pd-nav-items` (the three destinations from `NAV_MAIN`, then the Admin and Sysadmin groups from `NAV_GROUPS`, each preceded by a `.pd-nav-sep`) and `.pd-nav-actions` (account button with initials avatar + email, bell, "© 2026 PDash" shown only in the open sidebar). `NAV_GROUPS[i].roles` gates visibility (Admin: admin + sysadmin; Sysadmin: sysadmin). The menu label is the single source of the page name: `js/lib/page-names.test.js` requires `<title>PDash — <label>` and the breadcrumb of each page to equal it. Labels: Pipeline, Portfolio, Planning, Master Data (the Config page), Timesheets, User Admin, Team, Attribute Lists, DB Reset, Terms & Conditions.

**Icons.** `NAV_ICON_PATHS` + `navIcon(name, size = 'sm')` (`'sm'` 14px, `'md'` 16px): inline SVG, `viewBox="0 0 16 16"`, `currentColor`, `aria-hidden`; unknown name → `''`. No emoji remains in navigation, dropdowns, the three modal titles (change password, profile, send notification) or the desktop-notification banner (built with `innerHTML` from constants only).

**Behaviour.** `navLayout()` → `'small' | 'open' | 'rail'` (1024px media query + `data-sidebar`; `'open'` when `matchMedia` is missing). `navSetCollapsed(collapsed)` toggles `data-sidebar="collapsed"` on `<html>` and `PDash_sidebarCollapsed` (storage errors swallowed) and syncs the button's `aria-expanded`/`aria-label`. `navWireGroups(root)` (small screens): one group open at a time, outside tap / Escape / a `matchMedia` change to ≥ 1024px close all, Escape returns focus to the group's toggle. `navPopperConfig(...args)` is the Bootstrap `popperConfig` function of `#nav-account-btn` and `#nav-notif-btn` (defaults accepted as first or second argument): `bottom-end` below the avatar/bell on small screens, `right-end` (no flip, offset 10px, padding 10px) otherwise. `navRefreshAccount(user)` rewrites avatar initials and email after a profile save; the save handler sets both `first_name`/`last_name` and `firstName`/`lastName` on `window.__navUser` because `/auth/me` returns camelCase while the profile endpoint returns snake_case.

**CSS contract (`css/style.css`).** `#nav-container` is a fixed navy column (≥ 1024px, width `--sidebar-w`) or a fixed-height navy bar (`--nav-top-h` 111px) before the script renders, so nothing jumps. `.pb-board-root` height is `calc(100vh - var(--nav-top-h) - var(--breadcrumb-h))`. The nav is at `--z-fixed` (300) and rises to 1050 only while a dropdown or group panel is open (`:has(.dropdown-menu.show, .pd-nav-group.open)` on `#nav-container` and `.pd-nav`) — a bug found in the browser: `team.html`'s detail panel (z 1045) clipped open menus. `--breadcrumb-h` was measured at 32px (the earlier 33px left a 1.1px gap).

**Bugs found along the way.** (1) The first task's PowerShell rewrite added a UTF-8 BOM to 15 HTML pages — caught in review and stripped; later tasks edited with byte-safe tools. (2) The `/auth/me` user is camelCase but the profile-save handler wrote snake_case, so avatar initials would have stayed stale after a profile edit. (3) The z-index clipping above, and a white focus outline invisible on the white group panel (now magenta).

**Known open items.** `js/core.js`'s `updateNavState()` still queries `.nav-main-tab` (matches nothing, dead code, `core.js` was not edited to avoid a version bump); page headings in `portfolio.html` ("Project Portfolio") and `planning.html` ("Resource Planning") keep their old wording (page content, out of scope); unescaped `first_name`/`last_name` in the Send Notification recipient `<option>`s (pre-existing, candidate stored-XSS, separate hardening item); the 1050 literal has no token; widths below 1024px were verified through same-origin iframes only. Cache versions after this cycle: `nav.js?v=14`, `style.css?v=19`, `notifications.js?v=3`, `tokens.css?v=9`, `core.js?v=11`.

## Rail tooltips (follow-up to B2, 2026-10-02)

Branch `worktree-navigation-rail-tooltips`, merge `af16592`, frontend only, no spec/plan (a bounded change designed in chat; this section and the finish-cycle report are its record). Request: in the collapsed sidebar the native browser `title` of the icons should be replaced by an HTML/CSS tooltip shown next to the rail at the icon; with the sidebar open the standard title stays; the avatar and the bell get the same treatment.

**Behaviour.** Only in the rail (`navLayout() === 'rail'`: ≥ 1024px and `data-sidebar="collapsed"`). Targets are the elements with `data-tip`: every `.pd-nav-item` (top-level entries and the Admin/Sysadmin entries — in the rail the group panels are permanent, label-less rows, not a flyout, so they need it too), `#nav-account-btn` (text = the user's email, refreshed by `navRefreshAccount`; "Account menu" if there is none) and `#nav-notif-btn` ("Notifications"). `navItemHtml` now emits `aria-label`, `data-tip` and `title` per item: the label span is `display:none` in the rail, so without `aria-label` removing the title would leave the link nameless.

**Mechanics.** `navApplyTitles()` removes `title` from the `.pd-nav-item[data-tip]` in the rail and restores it from `data-tip` otherwise (open sidebar and screens < 1024px keep the native title); it runs at init, in `navSetCollapsed` and on the 1024px media-query change. `navWireTooltips(root)` (called once from `initNav`) delegates `mouseover`/`focusin` on `root` to show the single `#pd-tooltip` element: created lazily, appended to `<body>`, placed with `position: fixed` at `rect.right + 10` / `rect.top + rect.height / 2` (the CSS `translateY(-50%)` centres it). It is not a `::after` inside the item because `.pd-nav-items` scrolls (`overflow-y:auto`) and would clip it. It hides on `mouseout` (unless the pointer moves between children of the same item), `focusout`, `click`, Escape, `show.bs.dropdown` (so it never overlaps the avatar/bell menu), `scroll` of the items container, window `resize`, the media-query change, `navSetCollapsed`, and when its anchor is removed from the DOM (a `MutationObserver` on `root`). CSS (`css/style.css`): `#pd-tooltip` is navy (`--brand-navy`) with `--text-inverse` text, `--text-sm`, `max-width: 280px` with ellipsis, `pointer-events:none`, hidden until `.show`, `z-index: 1051` (above the nav raised to 1050 while a menu is open, below Bootstrap modals at 1055). Guards: `js/lib/nav-layout-guard.test.js` (position/z-index range/tokens/ellipsis), behaviour in `js/lib/nav-tooltip.test.js` (31 tests).

**Review and verification.** Verified in a real browser on the isolated branch stack (gap 10px and vertical offset 0 on every tested item, the avatar and the bell; no `title` in the rail; no custom tooltip with the open sidebar or in iframes below 1024px). The code review's round 1 (3 low findings) was fixed in the same cycle: resize and programmatic collapse now hide the tooltip, and a re-render of the navigation under the pointer is handled; its finding that group entries "duplicate a visible flyout label" was a false positive (no flyout in the rail) and is pinned by a regression test instead of a behaviour change. Round 2: no findings. Cache versions after this change: `nav.js?v=16`, `style.css?v=20`.

**Not verified / open.** A real Tab key press (the browser check used programmatic `focus()`/`blur()`); windows shorter than 640px; after a click hides the tooltip it reappears only after the pointer leaves and re-enters the item (accepted).
