# js/costgrid.js

Shared cost-grid business-logic library: loaded unmodified by `pipeline.html` as globals, and by `costgrid.html`'s own Vue rewrite via the bridge pattern (no longer loaded by `planning.html`, whose Vue migration confirmed it made no genuine calls into this file beyond two now-removed page-local no-op overrides) — decided 2026-07: this file is a permanent shared Vanilla service layer (not migration debt awaiting a future rewrite), with exactly 2 consumers today (`pipeline.html`, `costgrid.html`); see `docs/superpowers/specs/2026-07-27-costgrid-js-fate-design.md` for the rationale.

This file holds the full implementation narrative for `js/costgrid.js` — function-by-function detail, cycle-by-cycle fixes, first-attempt bugs. `CLAUDE.md`'s File structure entry keeps only a one-line pointer; when working on this file, read this file, not that line, for the detail. See `/sync-docs`'s routing rule for where future changes to this file should be written.

## Bridge pattern

`renderCgEditor()`/`renderCgVersionTabs(cg)`/`showCostGridEditorView(cgId, versionId, opts?)` are thin functions delegating into `costgrid.html`'s mounted Vue instance through a module-level `_cgVueApp` reference — every other function below that calls one of these three at its tail needs no changes. The imperative rendering functions this file used to own for its own page (`renderCgEditor`'s ~700-line innerHTML builder, `cgBindEditorEvents`, `cgApplyEditorLock`, `cgRefreshTotals`, `cgRefreshPhaseDates`, `cgRenderRoleList`, `cgFindTask`) were deleted entirely once `costgrid.html` moved to Vue; `cgComputeTaskTotals`/`cgComputePhaseTotals`/`cgComputeGrandTotals`/`cgComputeColumnTotals` relocated to `js/lib/costgrid-calc.js` (vitest-covered), `window.*`-bridged under the same names so `pipeline.html`'s unchanged detail-panel call sites are unaffected. `showCostGridEditorView()`/`renderCgVersionTabs()` log a `console.warn` (previously silent) if called before the `_cgVueApp` bridge is set. `_pbCloneSource` was removed (2026-10-07, see "New Proposal / Clone without a modal" below) once nothing read it any more.

## Delete flows

Clone + Delete Draft buttons in editor toolbar; `cgConfirmDeleteGrid(cgId, name, onSuccess?)` and `cgConfirmDeleteVersion(cgId, verId, label, onSuccess?)` both accept an optional callback (defaults to a bare `renderPipelineBoard()` call if omitted — a global that only exists on pre-Vue pages; every live caller on `pipeline.html` passes a callback that bumps its own Vue `refreshTick` instead); `cgImportAll()`'s post-import refresh guards the same call with `typeof renderPipelineBoard === 'function'` for the same reason. `cgConfirmDeleteVersion(cgId, versionId, versionLabel, onSuccess)` delegates to `cgConfirmDeleteGrid(cgId, cg.name, onSuccess)` when the cost grid has only one version (instead of blocking with an `alert()`) — deleting a proposal's only version now deletes the whole proposal, since every proposal always has at least one version.

## New Proposal / Clone without a modal (2026-10-07)

`cgCreateNewGrid()` and `cgCloneGrid(srcCgId, srcVerId)` no longer read a name from a Bootstrap modal — both act immediately and redirect into the editor. The two name-prompt modals (`#cgNewGridModal`, `#cgCloneModal`) and their Create/Clone button listeners were removed from `pipeline.html` and `costgrid.html`; `openNewProposalModal()`/`openCloneModal()` (both pages' Vue methods) became `createNewProposal()`/`cloneProposal(cgId, verId)` (pipeline) and `cloneProposal()` (costgrid, no args — uses `this.cgId`/`this.verId`), which just `await` the global function then do their own page bookkeeping.

- **New Proposal** always names the grid `'New proposal'` and calls `showCostGridEditorView(cgId, verId, { focusName: true })`; `pipeline.html`'s override of that global appends `&focus=name` to the redirect URL. `costgrid.html`'s cold-load `created()` hook checks that query param after `openVersion()` resolves: if present, it focuses and selects `#cgProjectName` (skipped when `isLocked`) inside `this.$nextTick`, then removes the param with `history.replaceState` so a page reload doesn't repeat the focus.
- **Clone** takes its source as parameters now (`srcCgId`, `srcVerId`) instead of reading the removed `_pbCloneSource` global, and names the copy `srcCg.name + ' — Copy'` — the same default the modal used to prefill. If the source version is the one open in the editor (`_cgActiveCgId`/`_cgActiveVersionId` match), `cgCloneGrid` now `await`s `cgAutoSave(true)` (after clearing `_cgAutoSaveTimer`) before loading the source structure, so an edit made just before clicking Clone is carried into the copy rather than lost to the cleared timer. The client id sent in both the `versions.create` call and the in-memory seed is sanitized through the new `cgApiClientId()` (`js/lib/costgrid-calc.js`): it returns the id unchanged only when it matches the UUID shape, else `null` — fixes `Clone failed: invalid input syntax for type uuid: "__unassigned__"` when the source proposal's client select held the frontend-only `'__unassigned__'` sentinel (`js/clients.js`), which the client-side model happily stores but a `uuid` database column rejects (the project-save path already had the identical sanitization in `js/api-sync.js`; this closes the same gap on the clone path).
- `cgCloneGrid()` still strips `taskId`/`phaseId` from the cloned structure via `stripCloneTaskIds()` (`js/lib/costgrid-calc.js`) before `saveStructure()`, then re-fetches the server-assigned structure — fixes a `duplicate key value violates unique constraint "tasks_pkey"` error (the backend reused a client-supplied `taskId` as the new row's PK, correct for a same-version re-save, wrong for Clone since the source version's tasks still exist under those IDs); `cgLoadStructureFromApi()` (`js/api-sync.js`) returns `true`/`false` (not always `undefined`) so callers can detect a failed load — `cgCloneGrid()` is the only caller that acts on it: the *source*-side load (before anything is created server-side) aborts the clone with a `showInfo()` error on failure, matching the pattern below; the *destination*-side load (after the new cost grid/version already exist on the API) shows a non-blocking "⚠️ Clone incomplete" `showInfo()` warning on failure instead, since aborting at that point would leave orphaned server-side state — the clone still opens in the editor either way and self-heals on the next successful load; this destination-side warning is suppressed entirely when `window.__pdashAuthRedirecting` is set (`js/api.js`) — the load failed because the session expired mid-clone and a redirect to `/login.html` is already in flight, so the warning would just be a confusing flash before navigation, not an actionable message (2026-07).
- Errors from either flow (API failure, missing source, failed source-structure load) surface via `showInfo('Could not create/clone the proposal: ' + e.message, 'Error')` — the project's standard in-page modal idiom — instead of the removed modals' inline `<div class="text-danger">`.

## Double-submit guards (2026-08, updated 2026-10-07)

`cgSaveVersion()` is `async` and guards `#btnCgSave` against a fast repeat click (`if (btn.disabled) return;`) — previously it called `cgAutoSave()` fire-and-forget and showed "✓ Saved" immediately regardless of whether the underlying PUT had actually completed; now the button disables for the real duration of the save and "✓ Saved" only appears once it resolves (`cgAutoSave()` itself never rejects, so no try/finally is needed to guarantee re-enable). `cgPublishDraft()`'s confirm-callback is protected against a fast repeat click by `showConfirm()`'s own guard (`js/core.js`) — an earlier, call-site-local `_cgPublishInFlight` flag was removed once that general fix landed, since it became redundant. `cgCreateNewGrid()` and `cgCloneGrid()` each guard themselves with a module-level in-flight flag (`_cgCreateInFlight`/`_cgCloneInFlight`, reset in `finally`) rather than a button-disabled check, since there is no longer a single dedicated trigger button to read (New Proposal and Clone now have multiple entry points — board card, detail panel, editor toolbar); the calling Vue method on each page also sets a reactive `proposalBusy` that disables every New Proposal/Clone control for the same window, as a second line of defense at the UI layer.

## Generate Project / program auto-link (2026-09)

`cgGenerateProject()` enters selection mode (task checkboxes); `cgConfirmAndGenerate()` opens `#cgProjectNameModal` (`costgrid.html`, replacing a former native `prompt()`) via the `_cgVueApp` bridge — `console.warn`s and no-ops if the bridge isn't set yet, matching `showCostGridEditorView()`'s convention. `cgSubmitProjectName(projectName, projectCode)` is the continuation: if `findExistingProgramForProposal()` (`js/lib/costgrid-calc.js`) already resolves a program for this proposal, generation proceeds straight to `cgDoGenerateProject()`; else if the current selection (recomputed fresh via `cgGetAssignedTaskIds()`/`cgGetAssignedTaskNames()`, not a stale snapshot from when selection mode was entered — a task added mid-selection via "+ task" must still count as free) leaves no task unassigned, same; otherwise `#cgCreateProgramModal` opens (name+code to create a new program, or a `<select>` — backed by a reactive `programs` array in `costgrid.html`'s own `data()`, since the classic global `getPrograms()` is unresolvable from inside a compiled Vue template's `with()` block — to link to an already-existing one), and `_cgPendingGeneration` holds the pending call until `cgResumePendingGeneration(programId)` (Create/Link) or `cgAbortPendingGeneration()` (any other dismissal, wired via `#cgCreateProgramModal`'s own `hidden.bs.modal`) resolves it.

`cgDoGenerateProject()` is `async` — exits selection mode *synchronously before* its two awaited API calls (project push, then linked-project sync — skipped if the push failed) so the "Create project" control can't be double-clicked mid-flight; `_pushProjectToApi()`'s return value (`js/api-sync.js`) gates whether the post-generation dialog offers to navigate to `project-config.html` or shows a "⚠️ Sync failed" warning instead. All 3 call sites of `cgDoGenerateProject()` attach `.catch(console.warn)` since it's never itself awaited by its callers.

`_cgEnsureAddToProjectModal()` (the old hand-rolled non-Bootstrap modal) was replaced by `#cgAddToProjectModal`, a real Vue-driven Bootstrap modal in `costgrid.html`.

## Publish + rate resolution

`cgPublishDraft()`'s success path ends with `window.location.reload()` — a Vue-reactivity gap (`_cgDraft.pipeline` is mutated via the raw global reference, bypassing Vue's proxy-based change detection, so `isDraft` and other Draft-only UI never invalidate) meant the Publish button and related controls stayed visible after a successful publish until a manual reload; its failure path uses `showConfirm()` instead of a native `alert()`, matching this file's established modal idiom.

Non-EUR role rate 3-level fallback (ratecard override → `role.rateOverrides[currency]` → EUR rate × factor) is no longer duplicated inline — `cgSyncRoleRatesToBaseline` and `cgPreviewRateChange` both now call the shared `resolveRoleRate()` (`js/lib/costgrid-calc.js`).

## Compact header + task assignment (R1–R5)

`_cgCompactHeader` (localStorage `PDash_cgCompactHeader`) toggles compact/normal blue header row via ⊟/⊞ button in the "Phase / Task" sticky cell — compact hides role move/change/dup/remove buttons and reduces header font to 10px.

`cgGetAssignedTaskIds()` + `cgGetAssignedTaskNames()` dual UUID+name check — assigned tasks have no ✕ button; `cgDoAddTasksToProject` and `cgDoGenerateProject` send `taskNames`; Generate Project button hidden when all tasks are mapped; `_cgEnsureAddToProjectModal()` is a singleton modal appended to `document.body` (z-index:10500). `cgGetVersionLockState(cgId, versionId)` — `other-version-active` reason (a sibling version already has linked projects) is whole-version and unchanged; `committed` reason now uses `js/lib/costgrid-calc.js`'s `isVersionCommittedLocked()` — locks only once the proposal's own pipeline is `Committed` **and** every task has been migrated to a project, not as soon as any single linked project reaches Committed.

`cgPropagatePipelineToProjects()` pushes `_cgDraft.pipeline` onto every entry in `_cgDraft.linkedProjects` whenever the editor's Pipeline `<select>` changes (`js/costgrid.js` `change` listener) — the only way a version's pipeline is ever changed (no drag-and-drop on the pipeline board), so `config.projects[].pipeline` for a cost-grid-generated project never goes stale relative to its source version. See `CLAUDE.md`'s "Pipeline stage: single source of truth" section.

## Money formatting (2026-10-01, money centralization cycle)

`cgFmtCurrency` was removed (money wrapper cleanup): call sites call `window.formatMoney(amount, code, window.__currencies)` directly (`docs/js/lib.md`); the rounded phasing amounts (`fmtA` in the phasing export helper) use `formatMoney(..., { rounded: true })`; a new draft version defaults to `currency: 'EUR'` (was the symbol `'€'`). `?v=39` (bumped 2026-10-07, New Proposal/Clone without a modal; `js/lib/costgrid-calc.js` moved to `?v=6` at the same time).

## API version rule (2026-10-07)

`POST /api/cost-grids/:id/versions` and `POST /:id/versions/:vId/duplicate` (`api/src/routes/cost-grids.js`) now refuse to create a version — `400 { error, code: 'VERSION_RULE' }` — on a proposal that already has a non-Draft version, via `versionCreationError({ role, hasPublishedVersion })` in `api/src/lib/project-rules.js`. This is a server-side close of a gap the UI already enforced (`+ New version` only shows on a Draft version; Publish deletes the other Draft versions), so only a direct API call against a published proposal could previously create a second version. A sysadmin (live role) is exempt, matching the same-file project-currency-lock rules' convention. No frontend caller in this codebase can hit the refusal through the UI — Clone always creates a brand-new cost grid, never a version on an existing one, so `cgCloneGrid()`/`cgCreateNewGrid()` are unaffected.
