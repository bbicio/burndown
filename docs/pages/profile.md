# profile.html — My profile

The user's own page: Details (read-only), Password, Privacy & data. Reached from the account menu (My Profile → `/profile.html`, Change password → `/profile.html#password`); no main-menu entry, `initNav('profile')` marks the account button active. Spec: `docs/superpowers/specs/2026-11-09-two-step-c1-profile-page-design.md`; boards `docs/superpowers/design/two-factor/redesign/15a-details.png`, `15b-password.png`, `15k-privacy.png`, `15ap-*`.

## Current state

- **Shell.** `#app-shell` / `.ph` (48 px navy avatar from `maskInitials`, title "My profile", sub-title `{First} {Last} · {role} · member since {date}`) / `.md-layout`. The Vue root `#app` holds the page head and the layout; the sub-navigation `<nav id="profileSubnav" data-subnav-set="profile" v-pre>` is rendered by `js/lib/md-subnav.js` (set `profile`: ACCOUNT Details, Password; PRIVACY Privacy & data), so it is the Master Data column ≥ 1024 px, a row of tabs 768–1023 px and the section selector below. `v-pre` keeps Vue off it; the page calls `mountMdSubnav()` on mount and on every section change.
- **Sections by hash.** `sectionFromHash(location.hash)` (`js/lib/profile-ui.js`): `#details`, `#password`, `#privacy`; empty or unknown → Details. The sub-navigation items are `#…` links and the phone selector sets `location.href` to the hash, so `hashchange` is the only path that changes section; back/forward work.
- **Details.** `GET /api/auth/me` values in a `<dl>`: first name, last name, email (lock icon), role chip, member since (`created_at`). Nothing is editable: name and email are changed by an admin (`admin.html` → Edit details…). Footer "Your details are managed by an admin." + **Request a change**, which opens the `.pd-drawer` `#rectificationDrawer` (textarea, `maxlength` 2000 with a counter; Send request disabled while blank) → `Api.auth.rectificationRequest` → `POST /api/auth/rectification-request`. Success: drawer closed, message cleared, `.pd-banner` "Request sent to the admins." (`role="status"`), focus back on the button (`hidden.bs.offcanvas`). Server errors stay in the drawer.
- **Password.** Sub-title "Last changed on {date}." only when `password_changed_at` is set. Three `type="password"` fields; `passwordFormState` gives the mismatch message ("Passwords don't match.") and enables Update password; `passwordStrength` fills the 4-segment bar (a hint only — the rule is the server's 8 characters). A refused current password comes back as `400 { field: 'currentPassword' }` and is shown under that field — it must not be a 401, which `apiFetch` would treat as an expired session and redirect to login. Other errors in a `.pd-banner--error` (`role="alert"`). Success: fields cleared, "Password updated.", `password_changed_at` set to now in memory.
- **Privacy & data.** "Your data in PDash": Profile, Your work, Agreements (`Terms & Conditions accepted on {date} · View` and Privacy notice, both to `/privacy-notice.html`; without an acceptance date only the two links). "Questions about your data?" only when `GET /api/app-settings/privacy-contact` answers an email (env `PRIVACY_CONTACT_EMAIL` / `PRIVACY_CONTACT_NAME`); an error or `email: null` hides it silently. Its mail icon is the page's own `mp-icon` (the shared set has none).
- **Dates.** `formatDayText` of the UTC day of each timestamp (`js/lib/dates.js`), so the text follows the site (`Jun 8, 2026`), not the boards' `8 Jun 2026`.
- **Left out on purpose** (spec §1.2): the boards' Save/Discard footer, the Password note about signing out other sessions, the Sign-in activity row, Download my data, and the Sessions / Notifications items (the SECURITY group has Two-step verification and Trusted devices since the second cycle).

- **Two-step verification** (`#two-step`, 2026-11-10). One method row (`Email code`, chip `Active`, "Codes are sent to {masked address} and expire after 10 minutes.") from `/me.two_step`, a `v-for` so another method is one more entry. The sub-navigation item carries the chip `Email`.
- **Trusted devices** (`#devices`). `GET /api/auth/trusted-devices` through the global `apiFetch`: icon by `kind`, label, chip `THIS DEVICE`, "Trusted on {date} · expires in {n} days" (amber under 10 days, `deviceExpiry`), Remove per row, Remove all (two or more, through the shared `showConfirm`; its OK button keeps the shared label). The sub-navigation item carries the count; both pills are put back after every section change (`applyChips`, because `mountMdSubnav` rebuilds the nav). A password change reloads the list.
- **Password note:** "Updating your password removes trusted devices."
- **Accepted deviations** (2026-11-10): the device count is a pill, not a plain number; dates read `Nov 10, 2026`; on a phone Remove sits under each device.

Stylesheet `css/profile.css` (`mp-` prefix). Tests: `js/lib/profile-ui.test.js`, `js/lib/md-subnav.test.js`, `test-api.js` (`A-me-2`, `PR-OF-01`, `RR-*`, `PC-01`, `PW-01`, `PW-02`); manual cases `GD-07`…`GD-12` in `TEST_CASES.md`.
