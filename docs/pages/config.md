# Master Data pages (formerly config.html)

Master Data UI — five pages, one per functionality: `master-clients.html` (Clients), `master-client-groups.html` (Client Groups), `master-pipelines.html` (Pipelines & POT targets), `master-roles.html` (Roles & rates), `master-currencies.html` (Currencies); admin **or sysadmin** only. `config.html` is now only a redirect to `/master-clients.html`.

This file holds the full implementation narrative for these pages — cycle-by-cycle detail, methods involved, first-attempt bugs, and report references. `CLAUDE.md`'s Pages table keeps only a one-line purpose description; when working on these pages, read this file, not that row, for the detail. See `/sync-docs`'s routing rule for where future changes to these pages should be written. **The sections below the "Split" section predate the split (2026-10-05) and were written when everything lived in `config.html`; each one now applies to the page named in the split table.**

## Split into five pages (2026-10-05)

The former single Vue app `config.html` (six `v-show` tab panels, one `loadAll()` for everything) was split into five pages; spec `docs/superpowers/specs/2026-10-05-master-data-split-design.md`, plan `docs/superpowers/plans/2026-10-05-master-data-split.md`, report `docs/superpowers/reports/2026-10-05-worktree-master-data-split-finish-cycle.md`. Priority of the cycle was "the split works": no redesign, no shared code, duplication across the pages accepted (a radical UI redesign was announced for the following days).

| Page | Former tab | Own data / API namespaces | Specifics |
|---|---|---|---|
| `master-clients.html` | Clients | `Api.clients`, `Api.ratecards`, `Api.roles`, `Api.currencies.active()` | `#clientRcModal` (inside `#app`, a Vue template over `rc`) + `openClientRatecard`/`saveClientRatecard`; preloads `window.__currencies` and loads the roles list (the rate card builds its non-EUR columns and "agency default" placeholders from them) |
| `master-client-groups.html` | Client Groups | `Api.clientGroups`, `Api.clients` | assign/remove clients |
| `master-pipelines.html` | Pipelines & POTs | `Api.pipelineYears`, `Api.pots`, `Api.reporting`, `Api.clients`, `Api.clientGroups`, `Api.currencies.active()` | `#potDetailsModal`, phasing views, `phasingTableHtml`/`projectPhasingTableHtml`, money preload |
| `master-roles.html` | Roles | `Api.roles`, `Api.currencies.list()` | per-currency rate fields filter `currencies` on `active`; delete guard (since 2026-11-04 see "Roles & rates" below) |
| `master-currencies.html` | Currencies | `Api.currencies` | `#crHistoryModal`, `#crRateConfirmModal`, `crEdit` built from the loaded list |

- **How it was built:** `docs/superpowers/plans/2026-10-05-master-data-split/split-config.mjs` sliced the original `config.html` (so every moved method/panel is byte-identical) and `check-split.mjs` verified syntax, balanced divs and that each page defines every member it uses. The generator cannot run any more (`config.html` is now a redirect); it stays as the record. After the final review two things were hand-adjusted in `master-clients.html` (the `window.__currencies` preload and the roles load).
- **Shell and naming:** every page is a standard page shell (`#app-shell` > `#nav-container` + `#app-main`) calling `initNav('config', …)`, `<title>PDash — Master Data</title>`, breadcrumb Home > Master Data > <section> since 2026-11-03 (so the Admin menu keeps highlighting "Master Data", `js/lib/page-names.test.js` maps the five files to id `config`). `js/nav.js`'s `config` entry points to `/master-clients.html`.
- **Lateral sub-menu:** superseded on 2026-11-03 by the generated sub-navigation, see "Shared shell" below.
- **Programs:** removed from the Config UI only (tab, panel, state, methods, `Api.programs.list()` in the load). DB, `/programs*` API, `js/programs.js` and the other pages (portfolio grouping and share, costgrid Generate Project, project-config "0. Program") are unchanged; consequence: no UI can rename or delete a program any more, programs can only be created from project-config/costgrid.
- **Redirect:** `config.html` = meta refresh + `location.replace('/master-clients.html')`, no shell, no Vue.
- **Final review fixes (before merge):** the Clients page originally lost the rate card's non-EUR columns (nothing set `window.__currencies`) so saving would have overwritten stored per-currency overrides with `{}`, and its "agency default" placeholders (roles not loaded/mapped); the sub-menu was not sticky (`align-self: stretch`). Pinned by `master-data-guard.test.js`; manual case `MD-08`.
- **Known leftovers (deferred minors):** load error text is "Failed to load data."; manual-case wording drift (section headings in `TEST_CASES.md` still say `config.html`).
- **Tests:** `js/lib/master-data-guard.test.js` (sub-nav and card CSS, per-page shell structure/names/access check/API namespaces/required pieces, redirect, nav entry), `page-names.test.js`, `nav-shell-guard.test.js`; manual cases `MD-01…MD-08`, `N-04`, `CN-01`, `CN-02`.

## Base state

Tab order (2026-09) is Currencies → Roles → Clients → Client Groups → Pipelines & POTs; the "Programs" tab button was hidden in 2026-09 and **restored 2026-09-30** ("🗂 Programs (N)" after Pipelines & POTs) so rename/delete have a UI entry point again — the panel, `programs` data and `saveProgram`/`deleteProgram`/`Api.programs.*` methods were never changed. `deleteProgram`'s native `confirm()` text now says a program with linked projects cannot be deleted (the backend `DELETE /programs/:id` returns 400 "Cannot delete program with linked projects"; it never unlinked projects); replacing the native `confirm()` is the deferred consistency point. Spec `docs/superpowers/specs/2026-09-30-ui-defects-data-loss-design.md`. Roles form's per-currency rate fields (`v-for="cu in currencies.filter(...)"`) now also filter on `c.active` — previously showed every non-EUR currency in the registry regardless of activation status, contradicting `PRD.md`'s own documented "one field per active currency" behavior; fixed to match, in both the create and edit paths (one shared form).

## Rate-update confirmation modal (2026-09)

The Currencies tab's per-row rate Save button now calls `confirmUpdateCurrencyRate(cur)` instead of `updateCurrencyRate(code)` directly, opening a new `#crRateConfirmModal` showing old→new rate and explaining the update does not retroactively affect any proposal/project already in the system — verified against `cost_grid_versions.currency_rate` being a frozen per-version snapshot (`api/src/routes/pots.js`'s fee subqueries always read `cgv.currency_rate`, never a live join to `currencies.current_rate`).

The modal does not close on Confirm click (`data-bs-dismiss` removed) — `updateCurrencyRate()` now gates on a `saving` reentrancy guard (`if (ed.saving) return;`, matching this codebase's established idiom elsewhere), shows a spinner and disables both buttons while the API call is in flight, and closes itself (`bootstrap.Modal.getInstance(...).hide()`) only on success; a failure keeps the modal open with the error shown inline, rather than closing first and surfacing the error next to an already-dismissed modal.

## Role delete guard and error-banner scroll (2026-09-25, Team role by id)

`DELETE /api/roles/:id` now also refuses (400, "Cannot delete role assigned to a team resource") a role that a `resources` row references — see `docs/api/resources.md`; `deleteRole()` shows the message in `globalError`. That banner sits at the top of the page, above the tabs, so a failed action on a long list (the Roles tab has dozens of rows) used to set the message out of view: the Vue instance now has `watch: { globalError(msg) { if (msg) window.scrollTo({ top: 0, behavior: 'smooth' }); } }`, and `deleteRole()` resets `globalError` to `null` before the request so a repeated identical failure still triggers the watcher. The scroll applies to every message that goes through `globalError` on this page, not just role deletes. Known leftovers: `deleteRole()` still uses the native `confirm()` (predates the project's one-modal-idiom rule), and other handlers that set the same message twice in a row without resetting it will not re-scroll. Also normal and not a bug: the browser prints the 400 in the console even though the code handles it. **Superseded on 2026-11-04** by the Roles & rates redesign (below): the refusal is shown inside the delete dialog, and the banner, the watcher and `confirm()` are gone.

## Money formatting (2026-10-01, money centralization cycle)

The Proposal/Project Phasing views and the POT amounts (EUR) call `formatMoney(amount, code, currencies)` directly (the former `fmtAmtC`/`fmtAmount` wrappers were removed; `docs/js/lib.md`); per-hour EUR rate labels (`€/h`) and exchange-rate displays are unchanged by design. The Currencies tab still loads `window.__currencies` itself (the page does not load `api-sync.js`).

- (2026-10-29, B-177) The page loads every currency (`Api.currencies.list()`, admin-only route), so a proposal in a currency deactivated since is formatted with its own locale and symbol (`TEST_CASES.md` PP-49).
- (2026-10-29, B-174/B-175) The cards, POT table, year row and Details list count each proposal once, through its reference version; the Details list leaves Canceled out. The page code is unchanged: the rule lives in the API.

## Rates and the POT amount through money.js (2026-10-30, currency cycle 2)

Spec `docs/superpowers/specs/2026-10-29-currency-c2-vue-rate-inputs-design.md`, report `docs/superpowers/reports/2026-10-30-currency-c2-vue-rate-inputs-finish-cycle.md`.
- **`master-roles.html`.** The form holds text (`rf.rateText`, `rf.overrideTexts[code]`, v-model), opened with `formatMoneyInput` (`'0'` for a stored 0) and reformatted on focus/blur only when it reads as a number; `saveRole` reads it with `readMoneyInput` (EUR for the base, the field's own code for an override): blank base → "Default rate is required.", invalid → "Enter a valid amount in X, e.g. …", blank override → none, a number (0 included) → stored. `fmtRate` is gone; the table uses `formatMoney`.
- **`master-pipelines.html`.** `potf.amountText` replaces `potf.amount`, same open/focus/blur rules; `savePot` reads it in EUR and refuses blank or invalid text. The label symbol comes from a `currencyInfo` template method.
- **Client rate card (currency cycle 3, 2026-10-30).** Spec `docs/superpowers/specs/2026-10-30-currency-c3-ratecard-design.md`. The modal is a Vue template over `rc` (`rc.rows[].texts[code]`, one text input per role and column, formatted on focus/blur in the column's currency like `master-roles.html`); an empty EUR field means the agency default and is saved as `hourlyRate: null`, a role with every field blank is not sent and loses its entry, unless it holds an override in a currency that has no column (inactive), which is kept and re-sent (the entries `PATCH` replaces the whole set, see [docs/api/config.md](../api/config.md)), an invalid text refuses the save as a whole. "Agency default" and the placeholders come only from the role (`roles.hourly_rate`, `rate_overrides[code]`), formatted with `formatMoney`; the client-less rate card is no longer read. The dead editor of `js/ratecards.js` is deleted.

Guards: `js/lib/master-roles-rate-input-guard.test.js`, `js/lib/master-pipelines-pot-input-guard.test.js`. Manual cases: `TEST_CASES.md` MD-09, MD-10.

## Clients & groups (2026-11-04, Master Data phase 2)

`master-clients.html` is "Clients & groups": Client Groups merged into it, and the client rate card is a sub-view of the page, not a modal. `master-client-groups.html` is only a redirect (meta refresh + `location.replace`) to `/master-clients.html?view=group`.

- **Views:** List and By group, switched by the `.md-seg` control in the card head; both show the same client rows and share the search (client or group name). A client's name and a group's name are edited inline; the form card is gone.
- **New client / new group drawer (2026-11-04):** "+ Add client", "+ Add group" and a client's "+ New group…" open one right-hand drawer (`.cg-drawer`, local CSS modelled on `master-pipelines.html`'s POT drawer; full width on phones), rendered while `cf.show || ng.show`, one mode at a time. It closes on ✕, Cancel, the scrim or Esc (`closeNewDrawer`); errors show inside it. `createClient`/`createGroup` are unchanged except that the switch to By group happens after a group is created, not when the form opens. Pinned by `js/lib/master-data-guard.test.js` ("opens the new-client and new-group forms in the side drawer").
- **URL state:** `?view=group` is By group (absent = List), `?client=<id>` is the rate card. A view change uses `history.replaceState`, opening a rate card `pushState`; `popstate` re-reads the URL. A `?client=` that names no client returns to the list with "Client not found.".
- **Group of a client:** set from the row's selector, the "⋯" menu (phone) or a group's "+ Add client" popover, always through `moveClient` (`js/lib/master-clients.js`): remove from the old group, assign to the new one, and a failed assign puts the old group back. The row's selector is disabled while its move runs.
- **Group delete:** `DELETE /api/client-groups/:id` answers `409 { code: 'GROUP_HAS_POT' }` when the group has a POT; `GET /api/client-groups` carries `pots: [{ id, year }]`, newest year first. The UI disables the trash with the years in its hint, and a 409 that still arrives (POT created meanwhile) lands in the page banner and reloads the groups.
- **Rate card:** loads and saves as the modal did (roles and rate cards re-read on each open, full replacement through `Api.ratecards.updateEntries`, payload built by `buildRatecardEntries`). Each cell's placeholder and caption come from `cellSource`, which calls `resolveRoleRate`. Roles are grouped by the code prefix before the first " - " (`Other` last). "Unsaved changes" compares amounts, not text, so focus and blur do not make a cell dirty; leaving with changes (← Clients, the breadcrumb crumb, back) asks for confirmation, and `beforeunload` covers closing the tab.
- **Layouts:** tablet (< 1024px) hides the rate card pill column below 900px, keeps Role and Client € sticky in the rate card and moves Agency € to the last column; phone (< 768px) shows client cards and a rate card of one currency at a time (`rcPhoneCurrency`), touch targets at least 44px.
- **Accepted deviations from the boards:**
  - Primary buttons use the app-wide magenta `.btn-primary`, the boards draw them navy.
  - The Agency € column is formatted by the money module (two decimals), the board shows whole euros.
  - The POT pill reads `POT · <latest year>` with ` +N` for further years; POTs have no name, the board's "POT · <group> 2026" cannot be drawn.
  - The group selector pill shows the group name up to 180px instead of truncating at about 100px.
  - The shell shows its sidebar at exactly 1024px, so a 1024px render is the desktop layout; the board's tablet frame (icon rail, tab row) is a different shell. The tablet layout starts below 1024px and was checked at 768px.
  - On tablet the rate card's "Only customized" and "How rates resolve" controls wrap to a second row instead of sitting beside the title.
  - On phone a long group name wraps to two lines in the group header, and the rate card has no Discard button (as on the board); the unsaved-changes guard still applies.
  - Out of scope in the boards and not drawn: Active/Archived, the Status column, the archive sentence, the extended role-family name, the sub-nav counts.
- **Fixed after the visual review:** the search field is 220px wide (the spec's 190px clipped its placeholder).
- **Tests:** `js/lib/master-clients.test.js` (filter, sections, rate sources, save payload, moves with rollback, URL state), `js/lib/master-clients-ratecard-guard.test.js`, `js/lib/master-data-guard.test.js` (redirect, no native dialog or emoji, breakpoints); API cases `CG-POT-01..03` in `test-api.js`; manual case `MD-14`.

## Pipelines & POTs (2026-11-04, Master Data phase 2)

`master-pipelines.html` is "Pipelines & POTs": three levels in one Vue app, each with its own URL, a Vue drawer for the POT detail, new year / new POT / edit target in the same side drawer as the POT detail (2026-11-05), and tablet and phone layouts. No server route changed; `Api.pipelineYears.create(year, active)` and `formatMoney`'s `{ symbol }` option are the two shared helpers it added.

- **URLs:** `master-pipelines.html` is the list, `?year=Y` the POT targets, `?year=Y&pot=<id>` the same with the drawer open, `?year=Y&phasing=proposal|project` the phasing. Level changes and the drawer use `history.pushState`, the Proposal/Project switch `replaceState`; `popstate` re-reads the URL. An unknown year returns to the list with "Pipeline <year> not found."; an unknown or other-year `pot` opens the POT targets without a drawer. Filters are not in the URL. The state is parsed by `parseMdpUrl` / `buildMdpUrl` (`js/lib/master-pipelines.js`).
- **List:** a new year is created hidden (`create(year, false)`); the Visible switch is disabled while its PATCH runs and restores itself on failure; Delete is disabled while the year has proposals (`offers`) or POTs (`deleteBlock`, because the server only refuses a year with cost grid versions and would leave the POTs orphaned) and a 409 still goes to `globalError`; the "⋯" menu is a Bootstrap dropdown. POT counts come from one `GET /pots` without a year.
- **POT targets:** the summary reads C + A from `pipeline-summary` for the whole pipeline; gap, achievement and the outside-POT note come from `gapToTarget`, `achievement`, `outsidePotCommitted`. The POT amount input keeps the pinned `readMoneyInput` wiring in one input shared by New POT and Edit target; Update target needs a reason; a server error stays in the form.
- **Drawer:** `GET /pots/:id/details?year=` is cached per POT in `potDetails` and invalidated by `invalidatePotDetails` after an update, delete or create. Proposals are listed Committed, Anticipated, Expected, SIP; dates come from `formatDayText`.
- **Form drawer (2026-11-05):** the computed `drawerView` picks `year`, `newPot`, `editPot` or `details` (a form wins over the details it was opened from); scrim, Cancel, Esc and ✕ go through `dismissDrawer`, which applies `mdpDrawerDismiss` (`js/lib/master-pipelines.js`): nothing closes while a save runs, ✕ closes the whole drawer, Cancel/Esc from Edit target return to the details. A form opened alone is 440px, one opened from the details keeps 560px. Edit target from the details does not change the URL; the row pencil of another POT closes the open details first. There is no bottom sheet and no table row form; boards 10.4b/d/e (inline rows) are superseded by this choice, and the Edit target amount carries the currency symbol like New POT.
- **Phasing:** one template for both modes, data cached per mode while the year stays open and dropped when leaving the phasing level. Totals come from `phasingTotals` (`eur` divides by `currencyRate || 1`; `original` gives one row per normalised currency, EUR first); cells are rounded without the symbol with the full amount in the tooltip. Draft and Canceled are always excluded.
- **Layouts:** 1024–1279px (the shell is already in its desktop layout there) and below 1024px hide the Committed/Anticipated columns, stack the summary, turn the two phasing buttons into a "Phasing" menu and open the drawer from the row; below 768px the list and the POTs are cards, the drawer is full screen with a bottom bar, and Edit target replaces the details in the same drawer. Touch targets are 44px on phone.
- **Accepted deviations from the boards:**
  - Primary buttons use the app-wide magenta `.btn-primary` and their disabled state is the shared one; the boards draw them navy and grey.
  - The SIP hatch has more contrast than the board's pale stripes and Expected is a tint of `--pipeline-expected-color` (no yellow token).
  - The phone detail keeps the "⋯" menu (Delete) in the drawer head; the board has none.
  - The tablet frame of the board (icon rail, tab row) belongs to a different shell; the page was checked at 1024px (desktop shell) and at the phone width, the 768px layout follows the same CSS block.
  - Out of scope in the boards and not drawn: "· N proposals" under each POT, "No project yet" rows and project grouping, the "Clients already in a group POT" hint, the export sentence, the "actuals" legend.
  - The reporting export (`/api/exports/phasing`) writes hours as `days * 8`, brief §7.5 says `days`; not changed here.
- **Fixed after the visual review:** the % and the amount in the list had no space; the new-POT target input clipped its placeholder; the drawer listed proposals in API order and used the old date format; at 1024px the POT table overflowed; the phone list showed the note and an extra inset.
- **Tests:** `js/lib/master-pipelines.test.js` (URL, counts, gap, outside-POT, targets, phasing filter and totals, with characterization of the old computed totals), `js/lib/master-pipelines-pot-details.test.js`, `js/lib/master-pipelines-pot-input-guard.test.js`, `js/lib/master-data-guard.test.js` (wide mode, responsive styles), `js/lib/money.test.js` (`symbol: false`). ## Roles & rates (2026-11-04, Master Data phase 2)

`master-roles.html` is "Roles & rates": a list grouped by team with one rate column per active currency, one side panel for create and edit, and a delete dialog that keeps the server's refusal inside it. No server route changed; the pure helpers are in `js/lib/master-roles.js`.

- **List:** groups by `extractTeam(code)` (unchanged rule), teams then labels with `localeCompare`; groups open by default, open/closed kept in memory only and forced open while a search or the Missing rates filter is on. Search matches label and code. A 0 or null EUR rate counts as missing ("No rate", amber row, counted in the group pill and in Missing rates) and stays saveable. Columns are EUR first, then each active non-EUR currency in API order (`rateColumns`). A non-EUR cell without an override shows "—" with the tooltip "≈ <EUR × current rate> from € × rate" (`fallbackRate` → `resolveRoleRate`); an inactive currency has no column. Amounts in the table have no symbol (the unit is in the header) and no decimals when they are whole; the full amount is in the cell's tooltip.
- **Panel:** Team + Role code are a UI over the single `code`: `splitCode` on open, `joinCode` on save; a code without " - " opens with an empty Team and is saved unchanged while Team stays empty; the `team` field is never sent. Team is a local combobox over the teams of the loaded roles, free text allowed; a new role starts in the last team opened or saved in the session, else the first team. The rate inputs keep the pinned `readMoneyInput` wiring, and every stored override is sent back, those of inactive currencies included. Esc, scrim, ✕ and Cancel close it, except while a save runs; Tab stays inside it and focus returns to what opened it, else to the role's button, else to "+ Add role". Its buttons are disabled and its fields read-only while a save runs. A Team and Role code left untouched send the stored code back unchanged. "Delete role" closes it before the delete dialog opens. The list keeps the uppercased code the server stores.
- **Delete:** a Vue-driven Bootstrap modal (`#roleDeleteModal`), not `showConfirm()` (which closes on OK). A 400 ("Cannot delete role used in cost grids" / "… assigned to a team resource") stays in the dialog with Delete disabled. Below 768px it is a bottom sheet.
- **Layouts:** below 1280px (the shell keeps its desktop sidebar from 1024px) the header shows a Missing rates toggle button and the search on its own row, the table drops Edit/delete for a chevron and a row opens the panel; below 768px a segmented control picks one currency, roles are cards, Missing rates is a chip, the panel is full screen.
