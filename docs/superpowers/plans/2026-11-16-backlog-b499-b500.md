# Link di condivisione con il default di `APP_URL` e `userId` validati (B-499, B-500) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** I link di condivisione usano l'`APP_URL` (con default) di `services/email.js` e un `userId` non UUID nelle cinque route di condivisione/notifica risponde 400 prima di ogni query.

**Architecture:** `appLink(path)` esportata da `api/src/services/email.js` costruisce ogni link di `cost-grids.js`. Le cinque route chiamano `isUuid` di `api/src/lib/input-rules.js` dopo il controllo di permesso. SEC-20/21 di `test-api.js` passano a un altro percorso che arriva a PostgreSQL.

**Tech Stack:** Node.js/Express, `node:test`, `test-api.js` via `scripts/run-tests.sh`.

**Spec:** `docs/superpowers/specs/2026-11-16-backlog-b499-b500-design.md`
**Branch:** `backlog-b499-b500`
**Risk class:** standard — route API e `services/email.js`; nessuna migrazione, autenticazione, money o operazione distruttiva

**Indipendenza dei task:** 1 e 2 sono indipendenti; 3 viene dopo 2 (sposta SEC-20, che oggi dipende dal difetto che 2 corregge); 4 viene dopo tutti.

## Global Constraints

- Messaggio esatto del 400: `userId must be a valid UUID`, corpo `{ error }` senza `code`.
- Il controllo sta dopo `canEdit` (403 resta prima del 400) e prima di ogni query che usa `userId`.
- `POST /api/notifications`: il controllo vale solo quando `userId` è presente; assente resta il broadcast.
- Un `userId` UUID valido conserva la risposta di oggi.
- Nessun punto di `api/src/routes/cost-grids.js` legge `process.env.APP_URL`.
- Testo per l'utente in inglese.
- Stack principale: solo `docker compose restart api` al Gate 4 (deroga di `CLAUDE.md`); nessun task tocca lo stack principale.

## Review Focus

1. `userId` non stringa (numero, oggetto, `null` nel corpo dello share) → 400, non 500 né un `toLowerCase` che esplode: `isUuid` rifiuta i non-stringa. Test in Task 2 (`userId: 123`).
2. `POST /api/notifications` con `userId: ''` → oggi è falsy e diventa un broadcast (admin) o un 403 (non admin): il comportamento non cambia, il controllo scatta solo per un valore truthy. Test in Task 2.
3. UUID maiuscolo valido → accettato come oggi (`isUuid` è case-insensitive). Test in Task 2 sullo share di cost grid (404 `User not found`, non 400).
4. `DELETE …/shares/:userId` con `:userId` non UUID da un utente senza permesso → 403 come oggi, non 400 (ordine dei controlli). Coperto dall'ordine nel codice; nessun test nuovo (serve un secondo utente non admin).
5. `appLink` con un `path` senza `/` iniziale → concatenazione semplice, nessuna normalizzazione: i chiamanti passano sempre `'/pipeline.html'`. Nessun test.
