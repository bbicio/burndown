> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `team.html` usable with ~150 people and dozens of unmatched names: page tabs, sortable table, a resource detail side panel (Details | Aliases | Experience profile) and a searchable select for the "Assign to" control.

**Architecture:** Frontend only. **Tech Stack:** Vue 3 (CDN, no build step), Bootstrap 5.3 (already loaded), vitest + jsdom for the pure module.

**Spec:** `docs/superpowers/specs/2026-09-25-team-ux-design.md`.

## Global Constraints

- No bundler/build step; runtime files served as-is. All user-facing text in English; no native `alert`/`confirm` (the page already uses `showConfirm`).
- `js/lib/team-ui.js` is a **versioned** file: its `<script type="module" src="js/lib/team-ui.js?v=1">` tag in `team.html` carries `?v=1`; every later edit to that file needs the bump in every page that loads it (only `team.html` today). Its exports are read via `window.*` only inside functions that run after mount (never at parse time).
- This plan modifies **no** other `js/*.js`, `js/lib/*.js` (besides the new file) or `css/*.css` → no other `?v=N` bump; re-verify with `git diff --name-only main -- js css` (expect only `js/lib/team-ui.js` and `js/lib/team-ui.test.js`).
- Nothing in `api/`, `docker-compose.yml`, or the DB changes. Never run `docker compose` against the main stack; verify with `scripts/run-tests.sh` / `scripts/test-branch.sh`. In a worktree copy the gitignored `.env` in first, run repo scripts with Git Bash (`& "C:\Program Files\Git\bin\bash.exe" scripts/...`), and remember `test-branch.sh up` does not apply new migrations (none are needed here).
- The panel sits at `z-index:1045`: above the page, below Bootstrap modals (1055), so the Edit and Confirm modals open on top of it.

**Design refinement (decided while planning):** the spec says `filterComboOptions` matches a substring of the label. It matches when **every whitespace-separated token** of the query is a substring of the label, so typing "rossi mario" finds "Mario Rossi" (people type names in either order, and the matching module itself is order-insensitive). A one-token query behaves exactly like the spec's substring match. Update the spec's §3 sentence accordingly in Task 1.

## Review Focus

- **Sort with missing values and ties.** A resource with a null `role_label`/`email` must not crash or scramble the order; equal keys keep a stable, name-based order in both directions; the input array is never mutated. Pinned by Task 1's `sortResources` tests.
- **Filter with accents, case, several words, empty query.** "jose" finds "José", "ROSSI mario" finds "Mario Rossi", an empty/blank query returns every option in the original order, no match → empty list. Pinned by Task 1's `filterComboOptions` tests.
- **Panel vs. modals.** Editing from the panel opens the modal on top; clicking inside the modal must not close the panel; Esc while a modal is open closes only the modal. Manual checks in Task 5.
- **Panel follows the data.** After Edit → Save the panel shows the new values; if the open resource disappears (deleted, reloaded away) the panel closes instead of showing stale data. Manual check in Task 5 (the `watch` on `selectedResource` in Task 3).
- **`combo-select` mouse handling.** Picking an option must register before the outside-click handler can close the list; keyboard Enter on "— none —" clears the choice and re-disables **Assign**; the control is disabled while its row is `_loading`. Manual checks in Task 5.
- **Tab switch.** Switching page tab while the panel is open closes it. Manual check in Task 5.

The Vue parts (panel, tabs, `combo-select`) have no automated harness in this project — as for every page-level Vue change here — so they are covered by the manual checklist in Task 5; the logic that can bite (sort, filter) is pulled into the tested module on purpose.

**Interfaces:**
- Produces (ES module exports, also bridged to `window`):
  - `sortResources(list, key, dir = 'asc')` — `list`: array of resource rows (`first_name`, `last_name`, `email`, `role_label`, `role_code`, `status`); `key`: `'name' | 'email' | 'role' | 'status'` (anything else falls back to `'name'`); `dir`: `'asc' | 'desc'`. Returns a **new** sorted array (input untouched). `name` = last name then first name; `role` = label then code; `status` = `active` before anything else; comparisons are case/accent-insensitive with numeric awareness; ties always fall back to name ascending, then original position (stable), regardless of `dir`.
  - `filterComboOptions(options, query)` — `options`: `[{ id, label }]`; returns a new array (same order) of the options whose label contains **every** whitespace-separated token of `query`, ignoring case and accents; a blank/absent query returns a copy of all options.

    expect(filterComboOptions(opts, 'i').map(o => o.id)).toEqual(['a', 'b', 'c']);

```js
// Pure helpers for team.html (Team UX cycle, 2026-09). No DOM, no Vue: unit-tested with vitest and
// bridged to window.* for the page's inline module script.

// Case/accent-insensitive, numeric-aware string comparison; null/undefined count as ''.
function cmp(a, b) {
  return String(a ?? '').localeCompare(String(b ?? ''), undefined, { sensitivity: 'base', numeric: true });
}

const nameCmp = (a, b) => cmp(a.last_name, b.last_name) || cmp(a.first_name, b.first_name);
const statusRank = r => (r.status === 'active' ? 0 : 1);

const KEY_COMPARATORS = {
  name: nameCmp,
  email: (a, b) => cmp(a.email, b.email),
  role: (a, b) => cmp(a.role_label, b.role_label) || cmp(a.role_code, b.role_code),
  status: (a, b) => statusRank(a) - statusRank(b),
};

// Returns a NEW array. Ties always fall back to name ascending, then to the original position,
// whatever `dir` is — so switching direction never shuffles rows that compare equal.
export function sortResources(list, key, dir = 'asc') {
  const sign = dir === 'desc' ? -1 : 1;
  const primary = KEY_COMPARATORS[key] || nameCmp;
  return list
    .map((item, index) => ({ item, index }))
    .sort((x, y) => (primary(x.item, y.item) * sign) || nameCmp(x.item, y.item) || (x.index - y.index))
    .map(entry => entry.item);
}

function fold(s) {
  return String(s ?? '').normalize('NFD').replace(/\p{M}+/gu, '').toLowerCase().trim();
}

// options: [{ id, label }]. Keeps an option when EVERY whitespace-separated token of the query is a
// substring of its label (case- and accent-insensitive), so "rossi mario" finds "Mario Rossi".
// A blank query returns a copy of all options; the input order is preserved.
export function filterComboOptions(options, query) {
  const tokens = fold(query).split(/\s+/).filter(Boolean);
  if (!tokens.length) return options.slice();
  return options.filter(o => {
    const label = fold(o.label);
    return tokens.every(t => label.includes(t));
  });
}

window.sortResources = sortResources;
window.filterComboOptions = filterComboOptions;
```
