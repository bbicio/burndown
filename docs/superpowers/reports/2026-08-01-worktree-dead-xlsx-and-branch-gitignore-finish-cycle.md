## Roadmap notes

- **New, unrelated finding surfaced during Gate 2 verification, not fixed in this cycle:** `nginx.conf`'s auth-gate (`location @to_login { return 302 /login.html; }`) produces an *absolute* redirect (`http://localhost/login.html`, confirmed via `curl -D -`) because nginx has no visibility into the external Docker port mapping — it always thinks it's serving on its own internal default port 80. On the main stack (externally published on port 80) this is invisible. On any isolated branch test stack (`scripts/test-branch.sh`, always a non-80 port, e.g. 8081), an unauthenticated visitor hitting a protected page gets redirected clean out of the branch's isolated environment and into the main stack's login page — a real, disruptive bug for the branch-testing workflow, and the reason this cycle's own Gate 2 fell back to static verification instead of interactive browser testing. Worth a dedicated Brief; not investigated further here (out of scope, isolated per this project's own audit-fix guardrail against fixing incidental findings inline).
