## How to read a row

**A row's `State` is worth exactly as much as its `Verified how` cell.** Every `open`/`closed` verdict
is a claim about the current state of the repository, which is the defect class that produced 19 review
findings in the cycle immediately before this file was created. A verdict reached by reading a report
rather than checking the code is not triage — the column is what makes the difference visible.

Five rules, each of them a failure this file cannot detect on its own:

1. **Write a path bare and backticked, with the line number outside it** — `` `api/src/routes/cost-grids.js` line 58 ``, never `` `api/src/routes/cost-grids.js:58` ``. `scripts/doc-paths-guard.test.js` requires a closing backtick (or, in a markdown link, a closing parenthesis) immediately after the extension; the second form is silently never validated, so the row looks checked when it is not.
2. **A path outside `ROOTED` is never validated**, however it is written. `scripts/lib/live-docs.mjs` enumerates the directories `docs`, `js`, `css`, `api`, `scripts`, `backups`, `handbook`, `.claude`, and a path whose first segment is anything else is invisible to the guard: every root-level file (`costgrid.html`, `test-api.js`, `PRD.md`…) and anything under a directory not on that list, `assets/` included. There is deliberately **no per-row marker**: an earlier version flagged some such rows and not others, and a marker present on some makes its absence read as "this one is machine-checked". To know which rows are affected, read the `Where` column — no figure is given here, because it moves with every row added. The guard's `ROOTED` test requires a real top-level directory as the first path segment, so `costgrid.html` and `index.html` are outside its reach. Re-check those by hand.
3. **Never move a row to `closed` from a report's own wording.** Run something. The `Verified how` cell carries what you ran.
4. **Never reuse a `B-NNN` id**, including after deleting a row. Two rows sharing an id make "which item did we close" unanswerable, and nothing checks uniqueness.
5. **A closeout with no accepted follow-ups and nothing closed writes nothing here** and says so in one line instead. A tracker that accumulates an empty row per cycle stops being readable.

An item whose state cannot be settled by a command is `open` with `Verified how: unverified — <what it
would take>`. That is an honest state, not a placeholder: silent omission is how the untracked reports
happened.
